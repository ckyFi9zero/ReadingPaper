# 对优化建议的核查与落实

日期：2026-09-17。依据：用户提供的建议、当前仓库源代码、实际导出及回归检查。

| 建议 / 问题 | 实际核查 | 本次处理 |
| --- | --- | --- |
| 保留静态技术和以论文为中心的结构 | 已具备，无重写必要 | 保留 9 篇、三阶段、原始两篇 HTML |
| 发布干净的站点 | 原来没有独立导出；资源链接包含 PDF、原始 Markdown、研究候选 | 本地完整 `_site` 与明确选择的 `_site-public` 分离；公开范围默认空 |
| 检查发布目录自身 | 原检查器只能按仓库读取 | 增加 `--root`，按导出清单检查实际输出及资源 |
| 注意大页面体积 | DHE-Net 15,230,403 字节，DSOR 6,548,193 字节，主要为嵌图 | 导出后分别为 62,970 / 51,210 字节 HTML，提取 32 张图，保留原图字节 |
| 更轻松补代码笔记 | 原来 Markdown 只支持 card 深读 | 三阶段均支持 Markdown，修正源文件相对链接，附代码笔记模板 |
| 分开笔记存在和核对状态 | 原来只显示是否有笔记 | 新增 reviews 登记；核对需日期/依据，旧笔记不自动升级 |
| 总览保存代码入口及待核对问题 | 没有对应字段 | 可选 codeUrl、openQuestions；不虚构论文问题或仓库链接 |
| 稳定构建 | 原来逐页写入，后段冲突可留下半更新状态 | 先渲染并检查所有目标；导出全部验证后再替换旧输出 |
| 分享排序后的列表 | 原来 URL 不保存排序项 | 排序写入并从 URL 恢复 |
| GitHub Pages 自动化 | 没有工作流 | 增加只手动触发的工作流，默认不部署，只接受公开导出 |
| 可复用模块索引、纳入两篇新综述 | 当前代码笔记为零，学术判断需要逐项源证据 | 暂缓填表，不凭网页字段捏造共性；可在实际阅读任务中补充 |
| 在线编辑、登录、知识图谱、统一算法库 | 当前阅读需求不依赖这些能力 | 未加入 |

核查范围：自动检查能证明文件、链接、状态映射和构建边界的行为，不能证明学术结论正确、所有内容可公开或 GitHub 上已经部署成功。本次没有执行推送、上传或公网发布。
