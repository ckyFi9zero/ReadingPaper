# readingpaper
This repository records the papers that I read carefully.
The goal is to track my reading progress, organize important research papers, and build a structured knowledge base.

For each paper, I record:

- Reading date
- Publication year
- Venue / journal
- Ranking or level (e.g., CCF / JCR)
- DOI
- PDF file stored in this repository

The PDF versions of papers are stored in the `pdf/` folder.

AI 接续讨论和维护项目时，可先阅读 [PROJECT_CHARTER.md](PROJECT_CHARTER.md)。其中包含当前进度、源文件与生成页面的区别、维护命令、验证边界和研究讨论偏好。

### 更新论文库

首次生成需要 Python 3.9+ 与 Markdown：

```bash
python3 -m pip install -r requirements-site.txt
python3 scripts/build_site.py
python3 scripts/check_site.py
```

新增论文时，在 `papers.json` 中增加记录；`slug` 对应论文目录。三个阶段均支持 Markdown 或已有 HTML，旧 `card` 字段仍兼容。示例结构如下，字段请替换成真实论文信息：

```json
{
  "slug": "paper-name-2026",
  "name": "Paper Name",
  "title": "完整论文标题",
  "year": 2026,
  "venue": "实际发表渠道",
  "readDate": "2026-09-17",
  "tags": ["LiDAR"],
  "summary": "基于已有笔记的一句话概括。",
  "stages": {"first-pass": "first-pass.html"}
}
```

将笔记保存为该目录下的 `first-pass.md`、`deep-read.md`、`code.md`，在 `stages` 中登记，例如 `"code": "code.md"`；生成器会生成对应 HTML。Markdown 中的相对图片/链接以源文件位置为准，生成时自动转换。已有 HTML 仍使用固定阶段文件名，可在 head 加入 `<script src="../assets/reader-nav.js" defer></script>` 获得统一导航。导航会自动识别当前阶段。

对于 Markdown 深读，使用 `"card": "paper-cards/对应目录/paper-card.md"`，不要同时登记 `stages.deep-read`。有 PDF 时添加 `"pdf": "pdf/文件名.pdf"`，没有则省略。目录索引默认由生成器维护；手写阶段页不会被覆盖。把待整理页替换为真实笔记时，去掉顶部 `Generated by scripts/build_site.py` 注释，并登记 `stages` 后重新生成。

普通浏览无需安装 Python 依赖。需要本地 HTTP 预览时：

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8765/`。也可将生成后的静态页面托管在 GitHub Pages 等静态服务器；本次仅在仓库中构建，未发布。DHE-Net / DSOR 原来指向仓库外的 PDF 链接已改为论文出版页，页面内嵌图像保留。

### 独立导出、来源核对与发布

详细步骤见 [网站维护与发布](docs/site-workflow.md)，本次建议的取舍见 [优化说明](docs/site-improvements.md)。

```bash
python3 scripts/export_site.py --profile local
python3 scripts/check_site.py --root _site
```

`_site/` 是包含现有阅读内容的本地完整导出，可打开 `_site/index.html` 阅读。导出会原样提取内嵌图片、单独加载并去重；它含私人研究笔记和引用的 PDF，不应直接公开。

公开范围由 `publish.json` 按论文及阶段明确选择，当前为空。准备好后用 `--profile public` 生成 `_site-public/`。GitHub Pages 工作流仅手动触发、只上传 `_site-public/`，默认不执行部署。当前没有推送、上传或发布。

`reviews` 分别记录整理状态和来源核对。旧卡片不自动标记已核对；要登记来源核对，必须填写日期和具体依据。代码阅读可参考 [模板](templates/code.md)；实际运行与静态阅读分开记录。

### Git 同步范围

`.gitignore` 排除本地导出 `_site/`、`_site-public/`、整个 `tmp/`（含已撤下深读的备份）、PDF 提取中间资料、Python 环境与缓存，以及本地配置和日志。它们只保留在本机，不会随本次 Git 提交上传。根目录和各论文目录的 HTML、共享资源、维护脚本、文档、正式笔记及已有 PDF 继续纳入版本管理。

推送仓库与发布 GitHub Pages 是两件事：`publish.json` 只控制网站导出，不控制 Git 仓库里的可见内容；如果仓库公开，已提交的文件也会公开。现有 Pages 工作流不会因 push 自动触发。

# Notes

Detailed notes for some papers may be written in the `notes/` folder.

Example:

```
notes/
├─ paper_name1.md
├─ paper_name2.md
```

These notes may include:

- Problem definition
- Key ideas
- Method overview
- Experiments
- Personal understanding
