STAGE 3 / 01总体框架与直观数据流

论文对一帧含雪点或车辆水花噪声的 LiDAR 点云，为每个点寻找近邻，用两层 NeighborHood（NH）卷积组成一个残差块，再经 Dropout 和全连接层输出逐点类别。点数沿模型保持不变，因此预测可直接对齐输入点。Sec. III-A–B，PDF pp. 3–4。

代码主线采用 train_wads.py / eval_wads.py 的实际配置：K=3 表示卷积边长，近邻数 k=K²=9；depth=1 是一个残差块，内部含两层 NH 卷积，通道为 4 → 32 → 32 → 2。首层另拼接距离通道，所以其实际核输入通道是 5。图中箭头表示前向数据流，底部支路在加号处相加；标签与损失不在此图中。train_wads.py:57–75

02 · 邻域索引：把空间相近变成可聚合的槽位

论文假设目标点在原文件第 1000 行，真正最近的点可能在第 8、200、7000 行。NH 卷积先用近邻索引把这些点取到一起，避免直接把相邻文件行当成空间邻居（III-A，p. 3）。

设计动机与证据

论文论文·设计动机：点云索引相邻不代表三维空间相近。作者用 kNN 构建可供卷积的邻域，并按距离升序排列；Fig. 2 的第 0 个位置是查询点本身，其他位置为近邻。

代码仓库说明·设计动机：同一帧的空间邻域不随训练轮次改变，README 建议缓存近邻，避免每轮重复计算。该意图不等于当前预计算脚本已可直接运行，入口缺口见第 05 节。

03 · 距离分支：首层多出一个可学习的通道

代码同样是第 9 近邻，可能离目标点 0.1 m，也可能很远。代码把距离信息与近邻的四维点特征并排交给首层卷积。没有单独距离模块图，论文依据是 III-A p. 3 的距离说明。

设计动机与证据

论文论文·设计动机：稀疏点可能有很远、缺乏局部关联的近邻，作者希望利用距离及可学习权重惩罚这类近邻；为避免重复，只在第一层加入距离（III-A 的第二条特征说明，p. 3）。

04 · NH 卷积：对近邻轴与通道轴同时求和

代码现在每个点都有一张 k×C 的邻域表。NH 卷积为每个近邻位置、每个输入通道配置共享参数，一次得到这个点的输出向量。它使用 einsum，不会真的把 N 张 3×3 图送入普通图像卷积。

设计动机与证据

论文论文·设计动机：直接对邻域应用卷积，减少通过额外 MLP 近似卷积或生成核的负担；邻域图与卷积核同样大小，无需滑动步幅，所有点可并行做一次 einsum（III-A，p. 3；Fig. 2）。这是作者的效率设计理由，性能仍须结合具体实现测量。

教学示例

假设只有 3 个近邻槽位、每点 1 个通道，取到 [2,5,1]，权重为 [0.2,0.3,0.5]，不加偏置，输出为 2×0.2+5×0.3+1×0.5=2.4。若只交换后两个邻居而不交换核权重，输出就改变。真实网络同时对多个输入通道求和，再输出 32 个通道；此例不代表论文实验。

推断Eq. (2) 是概括性的无限求和记号；代码实际只有 k 个排序槽位，直接乘加，没有显式执行 x−i 或翻转核。距离排序提供槽位语义，不提供规则空间方向。此层也没有使用相对于中心点的 xyz 差值，而是聚合标准化后的绝对 xyz 与强度。

05 · 两层残差块：邻域中的“特征云”再聚合

代码第一层把每个点转换成 32 维特征；第二层根据相同 ind 取出邻居的 32 维特征再卷积。底部分支把原始四维特征投影到 32 维后相加，输出仍有 N 行。

设计动机与证据

STAGE 3 / 06本阶段理解小结

代码已打通的数据流：去重后的逐点输入 → 以原始 xyz 建立固定近邻索引 → 标准化四通道 → 首层拼距离并做 NH 卷积 → 同一索引再次聚合特征 → 投影残差相加 → Dropout / FC → 每点二类 logits → 标签映射与可选输出。

论文关键设计：利用近邻槽位组织无序点云，用共享核直接对邻域求和，保持输入与输出点的一一对应；浅层残差结构服务于作者强调的效率目标。代码在当前实现中，距离是首层额外通道，k=9，只有一个残差块，两次 NH 之间无下采样、无新近邻搜索。

未核验仍未打通的连接：Spray 训练入口的 DeepTree、预计算脚本缺少 label_config、KITTI 测试模式、验证与测试 IoU 口径，以及当前计时和论文数字的对应关系。它们不妨碍读懂核心 NH 运算，但使“代码已定位”与“论文结果已复现”成为不同结论。
