04 · gap → insight 的关键过渡

转折位置新加入的信息写作判断与边界
P1-S2 → P1-S3真机遥操作的能力之后，首次明确提出硬件与数据形态绑定问题。首个具体 gap；不是只说“采集难”，还给出数据为何不通用。
P1-S4 → P1-S5新机器人可安全模拟，但任务资产与动力学难覆盖。第二个 gap 与第一条互补，而非重复。
P1-S5 → P2-I1从两类瓶颈直接转向新的组合。这里没有独立 observation 句；作者以设计分解回应问题。
D2-S2把控制任务改成跟踪轨迹，而不是与物体交互。最清楚的机制桥：训练对象变化 → 不再承担完整操作仿真的难题。
P3-S1 → P3-S2由接口标准进入对已有身体指令与单步目标的评价。gap 进一步缩小到表示与接口，且有明确判定轴。
P3-S2 → P3-S3 → P3-S4从旧接口限制到 task-frame 轨迹，再到两层消费/产生关系。核心设计与运作连续展开，但不等于已在引言证明所有效果。
P3-S5 → P4-S1从跨形态与预览收益到真实定位条件。“To support system deployment” 说明加里程计不是另一条无关主线。
Observation 不要替作者补得更漂亮

引言没有“我们首先发现一个新物理规律，所以……”这样的单独桥梁。更准确的重建是：互补的数据瓶颈 → 分工式框架 → 接口设计需求 → 轨迹接口。Fig. 4 和 §3 后来补充 task-frame 如何补偿身体扰动，不能倒置为引言已经逐步论证过的发现。PDF p. 4 · Fig. 4；Sec. 3

7.3 · “长”与“难”分开看

例句拆分方式它为什么放在这里
P1-S3主干① it is bottlenecked；主干② involvement makes data robot-specific / irrelevant；修饰：成本安全插入、e.g. 示例、whenever 条件。长度来自从障碍一路追到数据后果。它有多个嵌套与插入，理解难点不只是词数。
D2-S2By training … instead of … → we can bypass → 三项并列困难。虽长，但主干只有一个清晰操作—收益结构；并列资产、奖励、动力学扩展了信息量。
P3-S3we propose to use X as Y。在接口需求与旧方法不足之后，短句集中突出真正改动。
A6we demonstrate [deployment]；修饰：zero-shot、cross-embodiment、pretrained checkpoint、原形态插入、目标形态。主要难点是长名词短语和插入说明，而非大量从属谓语。
C1-S2With 接口条件 → formulation allows … yet is expressive … → 任务举例。用一条句子同时回扣直观示范与复杂表现力；任务枚举拉长句子，但逻辑轴仍明确。
