一、总体框架与数据流

论文 每个 BEV query 对应一个鸟瞰网格。每层先通过 temporal self-attention 从上一时刻 BEV 取时间信息，再通过 spatial cross-attention 从当前多相机特征取空间信息，六层后形成当前 BEV Bt，交给任务 head。（Sec. 3.1，Fig. 2）

6 相机图像当前帧 RGB 与相机/LiDAR 投影元数据。
ResNet + FPN四尺度、256 维的各相机图像特征。
40k BEV queries200×200 网格，覆盖 102.4m×102.4m。
TSA对齐并融合上一帧 BEV 与当前 query。
SCA把 3D pillar 点投影到可见相机并稀疏采样。
900 object queries六层 decoder 输出类别、3D box 与速度。

代码 基础配置把这条链具体化为：R101-DCN → 4-level FPN → 200×200×256 BEV → 6 个 BEVFormerLayer → 6 层检测 decoder → 900 个 object queries。输入模态明确关闭 LiDAR/radar/map，仅使用 camera 和 CAN bus 外部信息。

推断 方法的“统一接口”不是把相机特征直接拼成一个大 tensor，而是让固定 BEV 网格同时承担空间索引、历史状态载体和检测 decoder 的 memory；因此理解代码时应沿 BEV query 的生命周期追踪，而不是按仓库目录阅读。

三、逐模块解析

3.1 六相机输入、FPN 与 BEV queries

论文 Q∈RH×W×C 是网格化可学习参数；位于 p=(x,y) 的 query 负责对应 BEV grid cell。默认 H=W=200、C=256、每格 0.512m，BEV 中心为 ego car。（Secs. 3.2, 4.2）

输入基础配置中每样本 6 张相机图；训练时外面还有长度 4 的时间队列。图像先归一化、pad 到 32 的倍数。

代码 多尺度图像特征还会加入 camera embedding 与 feature-level embedding，再把各尺度空间位置展平并拼接。BEV query 则叠加 learned 2D positional encoding 和由 18 维 CAN bus 经 MLP 得到的运动 embedding。

3.2 Ego-motion 对齐与 Temporal Self-Attention

论文 先按 ego-motion 将 Bt-1 对齐到当前 BEV。移动物体仍可能有未知偏移，因此 TSA 用 deformable attention 建模当前 query 与对齐历史 BEV 的联系；首帧用 {Q,Q} 代替 {Q,B′t-1}。（Sec. 3.4）

Eq. (5)   TSA(Qp, {Q, B′t−1}) = ∑V∈{Q,B′t−1} DeformAttn(Qp, p, V)

Qp 是当前格点 query；p 是归一化 BEV reference point；B′t−1 是 ego-motion 对齐后的历史 BEV。论文明确说 offsets 由 Q 与 B′t−1 的拼接预测。

代码 num_bev_queue=2 是硬约束；offset/weight 的线性层输入为 2C，value 各自先投影，再对历史和当前两路做 deformable sampling，最后沿 queue 维取均值并加残差。

推断 Eq. (5) 写“求和”，当前代码显式执行两路均值，相差固定因子 1/2；论文未解释该归一化。当前 batch=1 配置也很重要：value[:bs] 与 stack/reshape 的排列在 batch>1 时需要重新审计，本页不把它外推为通用批处理实现。

3.3 Pillar reference points、相机投影与 Spatial Cross-Attention

论文 对每个 BEV query 沿 z 轴取 Nref 个高度锚点，投影到每台相机。只保留落在图像内且深度为正的 hit views，再在投影点附近用 deformable attention 采样，最后对 hit views 平均。（Sec. 3.3）

Eq. (2)   SCA(Qp,Ft) = 1/|Vhit| · ∑i∈Vhit ∑j=1Nref DeformAttn(Qp, P(p,i,j), Fti)
Eq. (3)-(4)   x′=(x−W/2)s,  y′=(y−H/2)s;   zij[xij,yij,1]T=Ti[x′,y′,z′j,1]T

代码 point_sampling 强制 fp32 并暂时关闭 TF32；投影坐标除以图像宽高得到归一化位置。SCA 只为可见 query 分配临时 buffer，六相机结果累加后按命中相机数平均，随后线性投影、dropout、残差。

论文—代码口径差异 论文 Sec. 4.2 写每个 3D reference point、每个 head 周围用 4 个 sampling points；基础配置将 MSDeformableAttention3D.num_points 设为 8，同时 num_points_in_pillar=4。源码把 8 个 offsets reshape 为 4 个高度锚点各 2 个 offsets。按当前 SHA 和基础配置静态展开，得到的是“每高度 2 点、总计 8 点”，并非文字所述“每高度 4 点”。

推断 indexes 与图像尺寸归一化分别读取 batch 的第 0 个样本，和配置 samples_per_gpu=1 相互吻合；若提高每卡 batch，不能仅改配置而假定行为仍正确。

代码 3D/2D reference points 与相机可见 mask 在进入六层循环前只计算一次；prev_bev 也不随层更新。每层的 TSA/SCA/FFN 参数来自独立构建的 transformer layer；本页未发现显式跨层共享权重。

推断 “refine BEV queries”指当前 query 表征逐层更新，不表示几何 reference points 也逐层回归；后者在 encoder 内保持固定。几何位置固定、特征内容更新，是这部分和检测 decoder 迭代 reference refinement 的关键区别。

3.5 Detection decoder、3D box、监督与 NMS-free 输出

论文 检测头以 Deformable DETR 为基础，改为单尺度 BEV memory，预测 3D boxes 与 velocity，只用 L1 监督 box regression，并端到端输出而不做 NMS。（Sec. 3.5）

Decoder 输入40,000×256 的当前 BEV memory；900×512 的 object embedding 被均分成 query position 与 query content；position 经线性层 + sigmoid 生成 3D reference point。
Head 输出每个 decoder layer 都产出 10 类 logits 与 10-D box code：(cx,cy,log w,log l,cz,log h,sin θ,cos θ,vx,vy)。

四、训练与推理全链路

训练：4 帧队列，只对当前帧反传

  1. 代码 数据集从当前帧之前 4 个索引中随机丢 1 个并排序，再加当前帧，组成 3 历史 + 1 当前；跨 scene 时置 prev_bev_exists=False。
  2. 代码 union2one 堆叠图像，并把 CAN bus 位置/角度改成相邻采样间增量。
  3. 代码 obtain_history_bev 切到 eval + torch.no_grad()，按时间递归计算前三帧 BEV；遇到新 scene 重置。
  4. 代码 当前帧走 backbone/FPN + BEV encoder，使用最后历史 BEV；随后 decoder/head 计算 6 层 focal + L1 losses。
  5. 论文 这对应“过去 2 秒随机取 3 帧、历史三帧无梯度、当前帧计算任务 loss”。（Sec. 3.6）

推理：跨帧保存一个递归状态

  1. 代码 测试 dataloader 按顺序提供帧；若 scene token 改变，清空 prev_bev。
  2. 代码 当前位置/角度减去上帧绝对值，得到 ego-motion 增量；首帧增量置 0。
  3. 代码 当前帧生成新 BEV 和 boxes；新 BEV、当前位置、角度写入 prev_frame_info，供下一帧使用。
  4. 代码 decoder 最后一层经 NMS-free coder 输出 Top-300 范围内 3D boxes、scores、labels。
  5. 论文 这对应按视频时间顺序在线推理、只保存上一时刻 BEV 的描述。（Sec. 3.6）

五、实现条件、差异与未核验项

项目已核对事实边界 / 影响
代码身份与版本官方代码 fundamentalvision/BEVFormer，master commit 66b65f3a…，该提交日期 2024-05-03。仓库同时含 BEVFormerV2；本页只跟踪 projects/configs/bevformer/bevformer_base.py 的原始 BEVFormer。
环境仓库文档指定 Python 3.8、PyTorch 1.9.1 + CUDA 11.1、mmcv-full 1.4.0、mmdet 2.14.0、mmseg 0.14.1、mmdet3d v0.17.1；模块导入自定义 CUDA deformable-attention extension。未运行 当前环境未安装这一旧版组合，兼容性、编译和数值行为未验证。
数据与权重需要 nuScenes full + CAN bus expansion、定制 temporal pkl，以及 R101-DCN/FCOS3D 预训练权重；README 另提供检测 checkpoint。链接存在不等于已下载或可加载；本页没有检查权重完整性与指标。
训练/测试入口tools/train.py 构建配置、插件、dataset/model 后调用 custom runner；README 用 8 GPU。tools/test.py 的非 distributed 分支含 assert False。按该 SHA 的入口，标准评估应走 dist_test.sh；不能把普通单 GPU 命令写成已支持路径。
论文 SCA 采样点论文写 4 点/高度锚点；基础配置 + reshape 实际为总 8 点 / 4 高度，即 2 点/高度。属于论文文字与当前实现口径差异；本页不猜测论文实验到底由哪一内部版本产生。
Encoder shift 注释encoder.py 注释称“保留 bug”，但同一 SHA 实际执行 shift_ref_2d = ref_2d.clone()，恰是注释声称的修正写法。注释与当前语句自相矛盾；不能据注释断言当前实现仍保留该 bug。
TSA 聚合论文 Eq. (5) 写两路求和；代码沿 queue 维做 mean。固定缩放差异；论文没有解释。
Batch 假设配置 samples_per_gpu=1；SCA 可见索引和投影归一化显式使用 batch 0，TSA 的 stack/slice 也与 B=1 紧密耦合。提高 batch size 需要重新核验，不能只改一项配置。
分割分支论文有 map segmentation；README Catalog 明示 segmentation code/checkpoints 未完成。未公开/未定位 Stage 3 代码链仅完整覆盖 3D detection。
性能论文报告 V100 上基础模型 BEVFormer module 130ms、总计 1.7 FPS；仓库 README 报 51.7 NDS/41.6 mAP。未实测 本次没有运行 benchmark，不能把论文/README 数字当作当前环境测量。

六、本阶段理解小结

已经打通的数据流

六相机图像先形成四尺度特征；40k BEV queries 在每层先读取一个递归历史 BEV，再把 4 个高度锚点投影到 6 个相机并稀疏采样；六层后得到统一 BEV。900 个 object queries 随后读取这张 BEV，以迭代 reference refinement 输出类别、3D box 和速度。

关键设计的代码落点

TSA 的“当前 + 历史”落在 num_bev_queue=2、2C offset/weight predictor 和 queue mean；SCA 的“hit views”落在投影 mask、camera rebatch、scatter-add 与 view-count average；递归记忆落在训练的 no-grad history loop 与推理的 prev_frame_info。

最容易误读的地方

训练的 4 帧不等于 TSA 同时注意 4 帧；encoder 的几何 anchors 不随层更新；检测 decoder 的 3D reference 才逐层 refine；所谓 NMS-free 仍会做 Top-300 与空间范围过滤。

仍未打通的连接

当前官方仓库没有论文分割分支；未运行旧版 CUDA 环境与 checkpoint；SCA 采样点口径、TSA sum/mean 和 shift 注释存在论文/代码或注释/语句差异。它们已被保留为显式缺口，而非用推测补齐。

阅读结论：BEVFormer 的真正实现主线可以压缩为“固定 BEV 几何索引 + 递归历史状态 + 按相机可见性稀疏采样 + DETR 式集合预测”。这四部分分别由不同代码路径完成，只有把数据队列、几何投影、两种 attention 和检测 decoder 串起来，Fig. 2 才成为可执行的调用链。
